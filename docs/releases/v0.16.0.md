# v0.16.0 — Portable Decision Resolution Evidence

TIS v0.16.0 adds the minimum portable contract required to carry TSMM decision-resolution semantics across independently authoritative implementations.

## Added

- `decision/decision-resolution-evidence.schema.json` for causal decision-transition evidence and material unresolved-condition state;
- explicit transition-basis categories for authority, evidence, policy, lifecycle, correction, and evaluation-context changes;
- an `authority_changed` assertion that prevents evidence-, policy-, lifecycle-, correction-, or evaluation-context changes from being misrepresented as authority changes;
- positive fixtures for evidence-based resolution with unchanged authority and unresolved peer pressure;
- release-gated validation that excludes peer pressure, repetition, reputation, and workflow progression from admissible resolution categories;
- TSMM semantic bindings for DecisionTransitionBasis and MaterialUnresolvedCondition with `authorityTransfer: false`.

## Semantic boundary

TSMM remains authoritative for canonical semantics. TIS owns portable serialization and validation only. A TIS artifact does not create authority, decide applicable policy, or determine whether a domain-specific concern is material.

## Research provenance

The TSMM work underlying this contract was informed by a read-only review of the independent Protocol of Care for Agents project:

- https://github.com/JessHines360/protocol-of-care-for-agents
- https://github.com/JessHines360/protocol-of-care-for-agents/blob/main/BRIEF.md
- https://github.com/JessHines360/protocol-of-care-for-agents/blob/main/experiments/SIMULATION_01_RUNBOOK.md

TIS does not adopt the upstream project's normative vocabulary. These references preserve research provenance only. No writes were made to the upstream repository.

## Compatibility

The change is additive. Existing v0.15.0 contracts remain valid for consumers that do not adopt decision-resolution evidence.

Existing TSMS and TRQP coordinated-release pins are unchanged. TIS v0.16.0 does not acquire stack compatibility solely because repository-local validation passes.

## Validation

```bash
npm run candidate:check
```

The candidate gate now includes `npm run decision-resolution:check`, alongside existing schema, semantic-alignment, lifecycle, governance, documentation, and publication validation.

## Residual limits

This release does not define domain policy, agent refusal semantics, A2A message types, or assurance certification. It does not claim that every decision transition requires a portable resolution record; consumers adopt the contract where causal resolution provenance is materially relevant.
